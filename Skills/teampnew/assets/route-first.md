# 每轮先路由，变更后维护目录记忆

- 每轮先读 `memory/INDEX.md` 与本页，依据当前任务的目录、位置、文件名称和关键词匹配路由，仅打开命中的少量记忆/项目文件/飞书文档。没有匹配项时向用户询问精确入口，或只在已明确的父目录做一层名称定位，不扩大到整个项目。
- 不默认递归列出 `memory/`、本地项目或飞书知识库，不以了解项目为由全扫描正文。查询已记录的路径/ID、列出指定父目录直接子项及该层必要分页允许。初次登记所有知识库只需入口及必要路由，不导出整库正文。
- 当前用户要求、当前文件和实测结果优先于记忆。历史路径只作定位线索；链接、ID、标题、父节点经实际验证才标注已验证。
- 新增文件或飞书节点后，登记准确位置、名称和 ID；删除后将原路由标记 `deleted` 并保留必要追溯；移动/重命名后更新位置、名称、相关链接及受影响目录索引。以本轮实际操作清单、已知路径或 Git 变更列表定位差异，不为记账扫描整库。Git 变更列表只可用作定位线索，不能把不明来源的改动当成本轮已验证动作。
- 路由记录分为 `local`、`remote`、`paired`：只有明确需要对应的条目才是 `paired`；代码、凭据或全部本地文件不得因为存在于项目就自动上传飞书。受管理的项目文件至少登记在对应目录路由分片；依赖、缓存、构建产物按项目已声明范围排除。
- 目录路由表只保存名称、位置、状态、用途及来源，不抄正文。只读路径/ID即能定位时不读额外内容。文件变更发生后在同轮结束前维护路由；记忆页面新增、移动、删除和状态改变，也要同步 `memory/INDEX.md` 或其局部索引。
- 检查模式只核对已登记路由及指定父目录一层范围内的名称和位置，不比较正文。不为通过检查创建空索引或补建 AGENTS，不擅自修复远端差异。无权限、超时或分页未完成是“无法核验”，不能等同缺失或一致。
- 写入失败、离线或远端结果未知时保留待核验状态；不得把计划写成成功。仅有已验证且属于本项目的持久信息才进入记忆，不记录密码、认证令牌或原始聊天日志。
- 保留已有 `AGENTS.md` 及用户规则；只追加缺失的协议入口。此工作流对原版“列出 memory 文件路径”的执行范围作更具体约束：只查索引命中的路径及必要父目录，不做全量列举。
