# teamPNew

以普通 Markdown 和相对路径保存可迁移记忆，适用于能读取技能与项目文件的 AI Agent。技能内置完整 `wiki-memory-agent`，不依赖原仓库、本机绝对路径或另一已安装技能。显示名为 `teamPNew`，标准调用标识为 `$teampnew`。

## 先确定入口

首次调用先让用户选择：

1. **新建总管理知识库项目**：登记用户的全部目标飞书知识库入口，建立跨项目目录和启动默认值。
2. **新建团队项目**：找到项目启动指南、框架、模板和产出目的地，按指南建立飞书文档及本地记忆。
3. **检查当前项目一致性**：仅核对已登记的目录位置和文件名称，不比较正文。

若用户当前请求已明确选择，简要复述所选模式后直接执行，不重复询问。只调用技能、未明确模式时，等待选择；不得擅自初始化或发起飞书写操作。确认当前项目根目录，不把技能安装目录当项目根目录。

## 共同执行约定

- **先记忆，后索取。** 先检查当前根目录的 `AGENTS.md` / `agents.md`、`memory/INDEX.md` 和明确声明的入口；读取索引命中的少量记忆。初始化模式在当前记忆不足时，先定点检查 `~/.teampnew/INDEX.md` 中的总管理定位条目（`~` 为实际用户主目录），方便同一电脑不同项目/工具复用。已有总管理索引时，只沿记录的精确路径或链接访问。也可用宿主已提供的相关长期记忆作为定位线索，但验证后才复用。无命中即停止扩搜，集中询问真正缺失的链接、指南或目标父节点。
- **迁移有边界。** 新电脑不会自动拥有旧电脑的本地记忆。未找到总管理索引时，索取其可携带的记忆文件/目录位置或云端入口；不得遍历用户磁盘、所有项目或整租户寻找。模式 2 不强制先运行模式 1。
- **只按路由读。** 每轮先读取短索引、固定路由规则，再按目录、位置和名称匹配，读取本任务必要文件。禁止以“了解项目”为由全盘递归列举或全文扫描本地项目、`memory/` 或飞书知识库。定点检查、明确父节点的一层列表及其分页允许；注册所有知识库不等于遍历所有文档。
- **外部能力按环境选择。** 飞书操作前读 [飞书访问约定](references/feishu-access.md)。有飞书连接器、MCP 或 CLI 就使用实际支持的能力；没有时清楚说明缺少连接/登录/权限。不能把仅收集链接、创建草稿或复制模板称为“已验证/已发布”。不在技能里保存认证信息。
- **内置原版与项目接入分开。** [内置原版](assets/wiki-memory-agent/README.md) 保持完整原文；[记忆接入约定](references/memory-contract.md) 说明如何部署及追加本技能固定规则。已有 `AGENTS.md` 不重建、不覆盖，仅补齐缺失协议及入口。检查模式不运行初始化脚本。
- **文件变化及时记账。** 每次新增、删除、移动或重命名本地文件/飞书节点后，在本轮结束前更新相应路由、目录索引和链接。只更新发生变化的条目；路由记忆自身和索引的增删改也要同步。失败或权限不足记为待确认，不能记为成功。

## 按模式执行

只读 [模式流程](references/modes.md) 中当前模式的部分。

- 模式 1/2：收集并验证输入 → 按 [记忆接入约定](references/memory-contract.md) 安装原版协议、登记上下文 → 定位/创建指南要求的产物并逐项更新路由 → 验证可按索引再次定位。
- 模式 3：先执行检查门槛；空项目、缺少有效飞书记忆或无法识别管理/团队类型时停止，说明需初始化。门槛满足后只查元数据；不补建记忆、不读取飞书正文、不擅自修复差异。

## 交付与持续生效

完成后用中文简述所选模式、已写入/复用的本地入口、飞书位置及链接、未完成事项。检查报告必须标注“仅目录位置与名称，未校验正文”，不能由部分通过推断整个知识库一致。

在新工具中确认它确实能加载本项目 `AGENTS.md`。不能自动读取时，将精确读取入口接入该工具当前支持的项目规则，或告知用户每次新会话显式引用；不要猜测 TRAE/WorkBuddy 等工具的隐藏配置路径。迁移时携带整个技能目录和所需项目 `memory/`，飞书登录需在目标环境重新建立。规则文件是协议，不代表已经安装每轮自动执行的 Hook。
