# 本地记忆接入与数据约定

## 原版与部署

技能携带 `assets/wiki-memory-agent/` 的完整快照，含原 README、`template/AGENTS.md` 和 `template/memory/INDEX.md`，相对结构及原文不变。`assets/wiki-memory-agent.manifest.json` 记录来源和逐文件 SHA256。不得运行时再下载另一版本，或用自写摘要替代原版协议。

实际项目部署的是 `template/` 的内容；README 留在技能资产中。项目真实知识登记在模板既有的 `memory/` 体系里，不建立第二套竞争的记忆根目录。

只有模式 1/2 在必需信息已取得后才执行初始化。先读当前根规则，处理明确冲突；不改写用户已有规则。使用本技能脚本（路径相对于技能目录，不是目标项目）：

```text
python scripts/bootstrap_memory.py --project <目标项目绝对路径> --date <用户本地YYYY-MM-DD> --dry-run
python scripts/bootstrap_memory.py --project <目标项目绝对路径> --date <用户本地YYYY-MM-DD>
```

脚本只部署协议和固定规则，不调用飞书、不生成虚构链接、不替代模式流程。它校验包内原版哈希，识别已有 `AGENTS.md` / `agents.md`，保留旧内容并追加缺失的完整协议及短路由补充；保留已有索引和主题页，仅添加缺失入口。遇见大小写重复入口、链接到项目外的写入路径或损坏的包会停止。重复执行无重复追加。`--dry-run` 不写文件。

脚本需要 Python 3.9+。目标环境没有合适的 Python 时，照以下同等步骤用文件工具操作，无需为此安装运行时：

1. 检查根目录是否存在任意大小写的 `AGENTS.md`，不要创建第二份。缺失时原样复制原版；存在时保留原文，仅在缺失时追加完整原版协议。发现与原规则直接冲突，先按用户已给出的约束处理，不能用模板覆盖规则。
2. 追加脚本中 `ROUTING_SUPPLEMENT` 对应的短规则（或读取已有安装实例中的同名块）：本技能具体路由约束优先于原版泛化的 memory 路径列举，模式 3 不自动初始化；每轮必读 `memory/workflows/route-first.md`。保留原版协议的全部内容。
3. `memory/INDEX.md` 缺失时复制原版，已有时合并。将 `assets/route-first.md` 复制到 `memory/workflows/route-first.md`，把 `{{DATE}}` 替换成用户时区日期；已有时最小合并而不覆盖用户修改。索引中将它标为每轮必读，且根 AGENTS 直接引用它，避免因普通任务关键词未命中而漏读。
4. 按下面的契约填入已确认的真实信息，给实际存在的主题页添加索引；清除初始化索引的“目前还没有持久项目记忆”空态句。保留无关已有条目。保存后定点回读索引及必要页面，检查相对链接可用。

## 页面与索引

沿用原版 YAML front matter：`description`、`type`、`status`、`updated`、`tags`。`type` 使用原版单数枚举。页面 `status` 与表中 `route_state` 是两个概念，不把 `pending` 填入页面 `status`。每页一个主题，索引只路由不抄正文；页长接近 200 行、索引接近 150 行时按真实范围拆分，最多两级索引，不建空分片。

| 规范位置 | 真实内容 | 读取时机 |
| --- | --- | --- |
| `memory/workflows/route-first.md` | 固定路由、禁止全扫描、变更后维护规则 | 每轮必读 |
| `memory/project/feishu-context.md` | 当前项目身份、类型、启动依据和产出目的地 | 项目启动、定位飞书、检查 |
| `memory/project/feishu-catalog.md` | 总管理的知识库注册表和启动默认值 | 仅管理模式建立；团队按已知入口读取 |
| `memory/project/feishu-routes.md` | 当前项目的本地/远端路由与对应关系 | 文件定位、目录变动、检查 |
| `memory/handoffs/feishu-pending.md` | 真实未完成写入、未知结果及恢复路径 | 仅发生阻塞时建立，解决后归档 |

总管理项目管理用户全部知识库入口，是该项目自己的明确范围；允许记录团队项目的定位入口，不搬运其他项目的正文或隐私。团队项目只保存本项目相关信息和总管理入口。迁移时可随项目携带 `memory/`；技能包本身不包含用户专属知识库数据。

### 跨项目定位入口

为支持先建立总管理、再从新团队项目调用，约定一个与工具无关的轻量入口：`~/.teampnew/INDEX.md`，其中 `~` 必须由当前环境实际用户主目录展开，不硬编码机器路径。这里只保存总管理项目名称、准确索引路径或云端目录 URL、管理范围和最后定位日期，不复制知识库正文或凭据。

- 模式 1 完成后将本次总管理入口登记到该文件；文件已有时最小合并、按精确入口去重，不覆盖其他管理项目。用户禁止全局写入或主目录不可写时跳过登记，交付准确入口，说明下个项目需显式提供。
- 模式 1/2 在当前项目记忆不足时可读取这个**固定已知文件**，再按名称/范围访问匹配的管理索引；有多个同等匹配入口时询问使用哪一个，不读取全部管理项目。路径不可用时请用户提供迁移后的入口，不搜索磁盘。
- 模式 3 不用它替当前项目补建记忆，也不以外部目录存在为由让缺失本地上下文的项目通过门槛。
- 新电脑可携带此入口和相应记忆目录；原绝对路径失效时必须更新为用户确认的新位置。另一工具必须有权读取该文件，不能将登记成功描述成跨设备自动同步。

该文件用普通 Markdown 表格即可，由执行技能的 Agent 按实际入口写入；初始化脚本只管理目标项目，不修改此用户级定位入口。

### 当前项目上下文

记录 `project_kind: manager|team`、项目名、管理范围说明、初始化状态 `ready|partial`、依据来源和验证日期。还须记录：

- 总管理索引入口：项目内相对路径、用户明确给出的外部路径或飞书 URL；跨机器路径不可用时如实标记，不能自行猜替代位置。
- 模式 1：知识库登记的覆盖范围（用户确认“全部目标库”还是部分清单）、知识库目录页入口；可获取时登记指南/框架/模板及团队默认目的地。
- 模式 2：启动指南、项目框架、模板的精确 URL/节点 ID；可以是一份文档中的不同章节，不能为了凑字段索取重复文档。产出位置必须有 `space_id` 和明确父节点（根节点则明确标识根），以及项目文件夹是否需创建的规则。
- 模式 1 未给指南/模板/默认目的地时记录“尚未配置”，总管理知识库目录仍可完成；之后模式 2 仅询问这些缺失项，不能声称模式 1 能凭空推导它们。
- `ready` 只在该模式必需的资源已定位且验证完成时使用；缺少访问能力/未完成产物时为 `partial`。

知识库目录每条至少有稳定的本地 `catalog_id`、名称、入口 URL、用途、`space_id`（已验证后）、已知入口/父节点、验证状态、来源。不能把 API 当前可见空间直接叫作用户所有空间；覆盖范围由用户清单或已明确的管理范围定义。

### 路由表

按实际项目需要填列，不创建充斥占位符的空表。记录：

| 字段 | 约定 |
| --- | --- |
| `logical_id` | 项目内稳定键，重命名不换键 |
| `kind` | `local` / `remote` / `paired`；只有已确认映射才使用 paired |
| `local_path` | 相对项目根路径，保留真实大小写；remote 可为空 |
| `remote_title` | 飞书实际标题，local 可为空；不能假设等于带扩展名的本地文件名 |
| `space_id` / `parent_node_token` | 飞书空间与父节点，根节点明确写 `ROOT` |
| `node_token` / `obj_type` / `obj_token` / `url` | 真实返回的节点/对象标识与访问入口，不猜 ID |
| `route_state` | `active` / `unverified` / `pending` / `deleted` / `conflict` |
| `verified_at` / `source` | 最近实际核验时间、来源指南/创建结果/用户确认 |

未验证的链接可记为 `unverified`，不伪造其父节点、ID 或验证日期。技术文件用 `local`，飞书独有资源用 `remote`；二者都能受目录管理，但不会自动相互复制。较大的源码目录按任务涉及的目录分片渐进登记，不为追求全覆盖在初始化时扫描全部文件。

## 后续变更

以本轮真实文件操作清单、已知路径和节点结果维护路由。新增记新条目；删除标 `deleted`；移动/重命名更新原条目并修复相对链接和受影响父目录。更新主题页后同步索引的摘要、状态和实质更新日期，无实质变化不刷时间。查到差异不等于获得远端删除/覆盖授权；检查报告与修复操作分开。

根协议补充和固定 workflow 均要求这些动作，不能只在当前对话中口头承诺。已有文件阻止安全合并时保留用户原文，记录未完成接入位置，不宣称规则已持续生效。
