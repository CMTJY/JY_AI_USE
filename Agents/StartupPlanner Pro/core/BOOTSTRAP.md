# StartupPlanner Pro v3 Bootstrap

本文件是平台无关的最小启动协议。不要在启动时读取全部 Agent 或技能。

1. 读取 `registry/route-index.yaml`，按完整信号目录判定最可能的领域；`taxonomy.yaml` 仅在需要解释槽位时按需读取。
2. 只读取命中领域的 `registry/route-domains/*.yaml`；复合请求最多加载 2 个领域分片，仍不确定则澄清。
3. 把用户请求解析为领域、任务类型、渠道、生命周期、目标产物和约束。
4. 复合请求先拆成可独立验收且依赖明确的原子任务。
5. 对每个原子任务执行硬过滤与评分，只保留最多 5 个候选。
6. 选择后才读取命中 Agent 正文和 Task Packet 所需的 1–3 个技能；完整注册表只用于维护验证，不进入启动上下文。
7. 输出可解释的 `route_decision`，再由宿主原生子 Agent 执行；宿主不支持时标记“单 Agent 串行角色模拟”。
8. 关键产物按 `core/quality-gates.md` 审核，最终只整合通过产物。

权限、删除、部署、推送和外部写入仍以用户明确授权为边界。
